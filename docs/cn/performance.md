# 性能说明

基准脚本会将数据构造与计算分开计时，并在隔离子进程中运行每次测量，报告计算耗时中位数、数据阶段峰值、默认结果峰值、首次物化权重的耗时，以及物化后的峰值：

```bash
uv run python examples/benchmark_efficiency.py --case dense-factor --runs 3
uv run python examples/benchmark_efficiency.py --case all --runs 3
```

可用场景包括：

- `dense-factor`：250 个资产、300 个日频观测；
- `monthly-factor`：2,000 个资产、2,520 个交易日及月频信号；
- `constrained-factor`：生产形状月频信号及稀疏交易限制；
- `portfolio-path`：一次连续计算，以及等价的 126 段 checkpoint 恢复计算。

2026 年 7 月开发机上的三次合成基准结果：

| 场景 | 数据中位耗时 | 数据峰值 | 计算中位耗时 | 默认峰值 | 首次访问权重 | 物化后峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `dense-factor` | 0.011s | 109 MB | 0.697s | 534 MB | 0.015s | 534 MB |
| `monthly-factor` | 0.523s | 1,136 MB | 2.904s | 1,146 MB | 0.930s | 1,743 MB |
| `constrained-factor` | 0.532s | 1,143 MB | 3.759s | 1,181 MB | 0.927s | 1,756 MB |
| `portfolio-path` | 0.101s | 331 MB | 合计 5.348s | 522 MB | 不适用 | 不适用 |

第三阶段的生产形状合成场景同时达到两个计算目标：月频评估为 `2.904s`，
低于 `5.5s`；受约束评估为 `3.759s`，低于 `5.0s`。默认峰值均低于
`1.19 GB`，明显低于 `1.72 GB` 目标。展开公开权重后仍需要约 `1.75 GB`，
但只有调用方显式访问权重时才发生，首次访问耗时也低于 `1.2s`。此前的
只读真实产物（92,125 条因子观测、2,003 个资产、2,534 个交易日和 29,807
条规则）本次已不在本地，因此旧的 `44.0s` 仅作为历史上下文保留，不表述
为本次重跑结果。

组合路径场景会分别报告两条路径。三次运行的中位数为：连续单次计算
`0.658s`，126 段 checkpoint 计算 `4.693s`，最大 RSS 为 `522 MB`；相对
第二阶段的 `0.716s` 和 `4.890s` 都有提升。

另一次与第二阶段提交的同进程 A/B 对照使用 450 个资产、2,520 个交易日和
126 个 TOP-50 月频快照。普通 `run_weight_backtest` 的三次中位数从
`0.320s` 降至 `0.191s`；两边都不包含数据构造时间。

主要优化包括：

- 按 observed-price 区间直接生成零收益段、恢复累计变动和缺口证据，不再
  默认收集稠密估值网格；
- 估值价格保持原公开 schema，但只在首次访问时生成并缓存；
- 每次评估只构造一次私有只读市场上下文，共享交易日、资产、价格观测、
  return、执行键和规则 retry 事件的整数编码；
- 分位数、TOP N、spread 和 lag 组合都使用稀疏持仓状态事件，不再构造
  “全部快照 × 全市场资产”的稠密目标网格；
- primary、quantile、spread 和 lag 组合共用一次市场扫描；默认 TOP N 和
  spread 直接复用 lag 0 结果；
- 在准备稀疏目标状态时直接生成缺价格诊断，不再为主组合重建稠密快照；
- IC decay 对每个源因子快照只排名一次，只有 return 样本不完整的组才重新
  排名；
- 交易规则和 retry 事件只编码一次，再用整数索引 NumPy 状态统一扫描；
- 最低手续费和净值路径使用预分配数组，换手和费用输入只保留非零交易事件；
- 完整结果在首次访问对应字段时才展开目标/执行权重，物化过程线程安全且缓存。
- 相关结果共享线程安全的执行键排序缓存；按需 signal diagnostics 只执行
  请求的 quantile、spread 或 lag 家族，并将同时请求的家族合并为一次扫描。
- 日频统一入口只校验并 collect 一次 Prediction，共用市场、日历与排名上下文，并只计算
  一次完整 `1..120` autocorrelation，供期限与路径两类结果复用；
- 十个日频分位组合通过一次长表 join 与 group-by 聚合，不构造十份组合副本；
- rolling IC 使用 Polars 分组滚动均值处理有效 observation，保持 null 不消耗窗口的语义，
  不再执行 Python 逐行循环。

所有优化都保持公开结果 schema 和交易语义不变。连续数值使用
`rtol=1e-12, atol=1e-12` 做回归验证；日期、资产、事件计数、blocked
trade 和 checkpoint 状态要求完全一致。

基准只统计计算。`bagelquant-workbench` 中逐月持久化、产物重载和 materialization
hash 仍可能主导 126 段生产链路的总耗时，应在应用层的后续优化中单独处理。
